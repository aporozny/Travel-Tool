# Lessons Log — Drift Discovery Engine

| ID | Date | Lesson | Apply how |
|---|---|---|---|
| L1 | 2026-07-08 | Hardcoded geography ("Bali Indonesia") silently capped the product's addressable market for months. | Never hardcode geo/market assumptions; resolve at runtime, fail loudly. |
| L2 | 2026-07-08 | A "cache-first, fetch-on-empty" pattern rots: partial data blocks refresh forever. | Cache decisions need a coverage/freshness threshold, not existence checks. |
| L3 | 2026-07-08 | Score weights drifted from their comments (+5 documented, +20 implemented) with no test to catch it. | Ranking logic must be unit-tested with ordering invariants. |
| L4 | 2026-07-08 | Interaction tracking was built but never wired into ranking — effort spent, value unrealised. | Close the loop in the same stage or explicitly defer with a ticket. |
| L5 | 2026-07-08 | Infra knowledge (tunnel, nginx, containers, backups) lived only in shell state until the DR runbook was written. | Every externally-visible service gets a runbook entry at creation time. |
| L6 | 2026-08-14 | Native binaries (Rust/N-API) can fail in ways invisible from documentation -- SIGILL on a CPU missing AVX2, MODULE_NOT_FOUND on musl vs. glibc. Only surfaced by actually deploying and reading the container's exit code/logs directly. | Never trust a clean `tsc`/build as proof a native-dependency-heavy service will run; verify against the actual target runtime. |
| L7 | 2026-08-20 | A third-party plugin not exposing a needed option (Anthropic's `thinking` param) doesn't mean it can't be used -- it can be patched durably. | Prefer a small, idempotent, loud-failing `postinstall` patch script (checked into the repo) over both silent `node_modules` hand-edits and forking the whole package. |
| L8 | 2026-08-20 | A Python patch script's string-replace silently doing nothing (no `assert`) let a real UI bug (a missing nav tab) ship past `tsc` and a clean build -- only caught by testing the live browser. | Every scripted find-and-replace against source needs an assert/count check; a silent no-op is worse than a loud failure. |
| L9 | 2026-08-20 | One shared `package.json` across two Docker services (backend, voice-worker) means a `postinstall` script's file dependencies (`scripts/`) must be copied before `npm ci` in every stage of *both* Dockerfiles -- fixing it in one wasn't enough. | When adding a `postinstall` script, audit every Dockerfile/stage that runs `npm install`/`ci` against that `package.json`, not just the one being actively worked on. |
| L10 | 2026-08-19 | Hardcoded secrets and unresolved placeholder strings ("dev-refresh-secret-change-in-production") survive silently in a public repo until someone specifically audits for them -- they don't surface as bugs on their own. | Treat "what's needed to go public" as an active security audit, not just a feature checklist. |
| L11 | 2026-08-23 | With no `Cache-Control` header set anywhere, browsers heuristically cache `index.html` -- a genuinely deployed fix can be invisible to a real user's browser for a long, confusing debugging session (this one looked like an account/auth bug for several exchanges) while it's actually just a stale bundle. Hit the same symptom twice in one session before it was fixed at the root. | Every SPA deploy needs `index.html`/the SPA-fallback route set to `no-cache, must-revalidate` from day one -- don't wait to hit this twice; verify with `curl -s -D - -o /dev/null <url> \| grep -i cache-control` after any nginx change touching static file serving. |
| L12 | 2026-08-24 | An SDK's error type can declare a field non-optional (`DuffelError.errors: ApiResponseError[]`) while still leaving it `undefined` at runtime for a response the SDK couldn't parse into its expected shape (confirmed live: a plain-text 403 body). Code trusting the type over the real runtime value crashed the entire backend process, not just the one request, since it ran inside a route's own catch block with nothing further to catch it -- and the same copy-pasted helper was already live in a second file, undetected. | Never index into a third-party error object's fields without optional chaining, even when the type says they're guaranteed -- a type describes the happy path, not every response shape a real API can return. When copying an error-handling helper into a second file, re-audit it for this too, not just the call site. |
